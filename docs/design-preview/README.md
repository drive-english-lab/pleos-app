# Native news design preview

Issue #6의 주차용 디버그 화면이다. Sites의 긴 대본·상단 통합 재생·오른쪽 연습 구성을 Compose로 확인한다. 기능 구현이 진행 중인 다른 브랜치와 독립적으로 `develop`에서 만들었다.

## 포함 범위

- 창작 기사 3편, 영어 원문 오디오 3개, 실제 길이로 측정한 문장 구간 18개.
- MediaPlayer의 전경 재생·정지·10초 이동·위치 이동, 미디어/음성 AudioAttributes와 AudioFocusRequest.
- 현재 문장 강조와 자동 스크롤. 직접 스크롤하면 따라가기를 멈추고 `현재 문장으로`로 복귀한다.
- 한국어 전체 번역 보기. 영어 재생과 한국어 문장을 임의로 동기화하지 않는다.
- 기사 목록, 창작 기사 정보, 말하기 질문과 명시적인 답변 예시, 기존 연결 점검 화면.
- Asta Sans 400/500/600, 블루, 시스템 다크 모드, 앱 창 너비에 따른 오른쪽 패널 전환.

오디오·글꼴·아이콘과 launcher 변경은 `src/debug`에만 들어간다. 추가 라이브러리나 권한은 없다. 릴리스의 launcher와 연결 점검 코드는 유지한다. OFL 1.1과 Lucide ISC 라이선스는 디버그 assets에 함께 보관한다.

## 확인한 환경

2026-11-12, Pleos Connect 2.1 / API 34 ARM64 / `Pleos_Connect_v2_1` / 사용자 10. 전체 디스플레이는 2560×1440, 160dpi다. 이 실행에서 앱에 배정된 영역은 `[853,90][2535,1300]`, 즉 1682×1210이었다. 웹의 16:9 전체 캔버스와 실제 앱 창 비율을 구분한다.

| 검증 | 결과 |
| --- | --- |
| `:app:assembleDebug`, `:app:assembleRelease`, `:app:lintDebug` | 성공 |
| AVD 설치·실행 | 성공 |
| 재생·정지 | 0:00 → 0:01, 정지 후 위치 유지 |
| 오디오 포커스 | 외부 차량 오디오 정책에 GAIN 소유자 등록 확인 |
| 10초 앞으로 세 번 | 0:01 → 0:31 |
| 번역·영어 대본 복귀 | 성공 |
| 연습·답변 예시·재생 복귀 | 성공 |
| 연결 점검 진입·뒤로 | 성공 |
| 시스템 다크 모드 | 실제 AVD 캡처 확인 |

자동 GPU 선택은 메모리 압력 때문에 소프트웨어 렌더러로 떨어졌고 기본 DrivingView의 Unreal 프로세스가 반복 종료됐다. 그 상태에서는 그 프로세스의 입력 영역이 앱 터치를 막았다. AVD 데이터 삭제 없이 `-gpu host`로 다시 시작한 뒤 위 조작을 확인했다. 앱 Activity의 예외와 구분한 환경 문제다.

## 다음 구현과 구분

직접 마이크, 인식·평가, Gleo, Supabase 읽기와 저장, 계정, 백그라운드 Media3 재생은 연결하지 않았다. 말하기 화면은 예시를 보는 디자인 시연이다. 대본·번역·직접 입력은 주차에서만 제공하는 제품 정책을 따른다. distraction-optimized 표시나 시스템 차단 해제를 추가하지 않았다. 이 변경에서 D 상태의 실제 미디어 사용 허용을 검증했다고 해석하지 않는다.
